# 技術選定

- **対象**：Akiko Portfolio（個人ポートフォリオサイト）
- **作成日**：2026-10-01
- **更新日**：2026-11-28（本番公開後の構成に合わせて更新）
- **状態**：確定。今後技術を変えたときは、この文書も更新する

## 1. 選定方針

優先順位（上ほど優先）：

1. **課題要件（MUST）を満たすこと**（Next.js App Router／Express／Prisma／PostgreSQL／Firebase 認証）
2. **仕組みを自分の言葉で説明できること**（就職活動で見せるため、動くだけでなく理由を話せる構成にする）
3. **秘密情報をブラウザへ渡さないこと**（DB 接続情報・内部 API キー・Firebase Admin の認証情報はサーバー側だけで扱う）
4. **無料枠で公開し続けられること**（閲覧頻度が低くても止まらない、または自動で復帰する）
5. **作品が増えてもコードを書き換えずに運用できること**（管理画面から登録・並び替え）

## 2. 技術スタック一覧

区分の意味：**課題指定**＝課題要件で決まっていたもの／**選択**＝自分で選んだもの。

| レイヤ | 採用技術（バージョン） | 区分 | このアプリでの役割 | 選定理由 |
| ------ | ---------------------- | ---- | ------------------ | -------- |
| 言語 | TypeScript 5.9（フロント・バック共通、`strict: true`） | 課題指定 | 全コード | 型で入力値や API レスポンスの取り違えを、実装中に見つけられる |
| 実行環境 | Node.js 24（`.nvmrc` で固定） | 選択 | Next.js・Express の実行 | 作成時点の LTS（長期サポート版）。手元・CI・Vercel を同じバージョンにそろえている |
| フロントエンド | Next.js 16.4（App Router）＋ React 19.2 | 課題指定 | 公開画面、管理画面、サーバー処理（Server Component／Server Action／Route Handler） | ブラウザと Express の間に Next.js のサーバー機能を挟めるため、秘密情報をブラウザへ渡さずに済む |
| CSS | Tailwind CSS 4 | 選択 | 画面のスタイル | Next.js のプロジェクト作成時に選べる構成で、しごとみっけのチーム開発でも使っていた。クラス名を書くだけで、スマホ向けの調整までできる |
| バックエンド | Express 5.2 ＋ helmet 8 | 課題指定 | 公開 API、管理 API、画像 API、入力チェック | フロントと分離した API サーバーとして、役割の境界が見えやすい。helmet で、安全のための HTTP ヘッダーをまとめて付ける |
| ORM / マイグレーション | Prisma 7（`@prisma/adapter-pg` ＋ `pg`） | 課題指定 | DB 操作、スキーマ管理、マイグレーション | `schema.prisma` がそのまま DB の設計図になる。SQL を文字列で組み立てないため、SQL インジェクションを防げる |
| データベース | PostgreSQL（開発：16 を Docker で起動／本番：Neon） | 課題指定 | プロフィール・実績・スキル・お問い合わせ・画像の保存 | 配列型（`technologies`）やバイナリ型（`imageData`）をそのまま扱える |
| 認証 | Firebase Authentication 12（メール＋パスワード） | 課題指定 | 管理者の本人確認 | パスワードの保管・照合を自前で実装しなくてよい |
| サーバー側の認証・認可 | Firebase Admin SDK 13 ＋ `httpOnly` セッション Cookie（5日間）＋ 管理者 UID の照合 | 課題指定 | ID トークンとセッションの検証、管理者かどうかの判定 | Cookie を `httpOnly` にすることで、画面上のスクリプトからセッションを読めないようにする。管理者は1人なので、権限テーブルを作らず UID の一致で判定する |
| 管理 API の保護 | 内部 API キー（`x-internal-api-key` ヘッダー、`timingSafeEqual` で比較） | 選択 | Next.js のサーバー以外から、Express の管理 API とお問い合わせ API を呼べないようにする | Express は Firebase のセッションを知らないため、サーバー同士だけが知る合言葉で守る |
| 画像の保存 | PostgreSQL の `Bytes` 型（`imageData`）＋ `imageMimeType`。JPEG／PNG／WebP、1MB 以下 | 選択 | プロフィール画像・作品画像 | 画像をリポジトリに置かずに済み、ストレージのサービスを別に用意しなくてよい |
| 入力チェック | 自作の検証関数（`backend/src/validation/`、`frontend/src/lib/admin-form-validation.ts`） | 選択 | ブラウザ・Server Action・Express の3段階で検証 | 検証ライブラリを追加せず、何を確認しているかをコードで直接読める |
| メール通知 | Resend（HTTPS の API を標準の `fetch` で呼ぶ） | 選択 | お問い合わせが届いたことを管理者へ知らせる | Render の無料プランはメール送信用のポート（SMTP）が使えないため、HTTPS で送れるサービスを選んだ。通知には個人情報を含めない |
| テスト | Vitest 4 | 選択 | 入力チェック・キャッシュ設定・通知などの単体テスト | スクールの教材やしごとみっけで使っていて、TypeScript をそのまま実行できる |
| Lint / Formatter | ESLint 9（フロント：`eslint-config-next`／バック：`typescript-eslint`）＋ Prettier 3 | 選択 | コードの問題の検出と、書き方の統一 | フレームワーク標準の設定を使う。整形を自動にして、見た目の差分がレビューに混ざらないようにする |
| CI | GitHub Actions | 選択 | PR ごとに整形チェック・Lint・テスト・ビルドを実行 | `main` へのマージ条件にして、壊れたコードが本番に出ないようにする |
| 開発用サーバー | `tsx watch`（バック）、`next dev`（フロント） | 選択 | 保存時の自動再起動 | ビルドなしで TypeScript を実行できる |
| コンテナ | Docker Compose（PostgreSQL のみ） | 選択 | 開発用 DB の起動 | PC に PostgreSQL を直接入れずに、同じバージョンの DB を再現できる |
| パッケージ管理 | npm | 選択 | 依存パッケージの管理 | Node.js に標準で付属する |
| ホスティング | フロント：Vercel／API：Render／DB：Neon | 選択 | 本番公開 | しごとみっけの個人デプロイで同じ構成を経験していた。どれも無料枠があり、GitHub 連携と自動 HTTPS に対応している |

## 3. 比較サマリ

| 論点 | 採用 | 不採用 | 判断根拠 |
| ---- | ---- | ------ | -------- |
| フロント／バック構成 | 分離（Next.js ＋ Express）。ブラウザは Express を直接呼ばない | Next.js だけで完結（Route Handler から直接 Prisma） | 課題要件。Next.js を間に挟むことで、内部 API キーと DB 接続情報をサーバー側に閉じ込められる |
| 管理 API の守り方 | 内部 API キー | Express 側でも Firebase のトークンを検証する | 認証の判定を Next.js の1か所（`require-admin.ts`）に集められる。Express には Firebase の認証情報を置かなくてよい |
| 未認証時の応答 | HTTP 404 | ログイン画面へリダイレクト／HTTP 401・403 | 課題要件。管理画面が存在すること自体を外部に知らせない |
| 管理者の判定 | 環境変数の UID と一致するか | DB に権限テーブルを持つ | 管理者は本人1人だけのため、テーブルを増やす必要がない |
| 画像の保存先 | PostgreSQL（`Bytes`） | Firebase Storage などのストレージ、`public/` に置く | 管理画面から差し替えられ、外部サービスを増やさずに済む。件数が少なく 1MB 上限なので DB の負担は小さい |
| 入力チェック | 自作の関数 | Zod、express-validator | 項目数が少なく、追加の学習なしで処理を追える |
| 公開画面のデータ取得 | Next.js のサーバー側に1時間とっておき、管理画面で保存したら作り直す | 表示のたびに Express を呼ぶ | Render の無料プランは停止から起動に時間がかかるため、閲覧者を待たせない |
| メール通知の送り方 | Resend の HTTPS API | Gmail などの SMTP | Render の無料プランでは SMTP のポートが使えない |

## 4. リスクと対応

| 技術 | 懸念点 | 対応 |
| ---- | ------ | ---- |
| Firebase Admin SDK | 14 系は、Vercel 上でログインが 500 エラーになった（ESM 専用の部品を読み込めない） | 13 系を使う。14 系に上げるときは、Preview 環境でログインを確認してから本番に出す |
| 依存パッケージ | Firebase や ESLint の中で使われている部品に、脆弱性の通知が出ている | 直接使っていない機能の部品で、影響は小さいと判断。親のパッケージを更新するときに一緒に解消する（#34）。`npm audit fix --force` は使わない |
| Prisma | CLI（7.10）とクライアント（7.9）のバージョンが少しずれている | 次に依存パッケージを更新するときにそろえる |
| お問い合わせフォーム | 公開後に大量送信されると、`Contact` テーブルが埋まる | 内部 API キー・ハニーポット（人には見えない入力欄）・全体で10分に10件までの制限で対応済み |
| 画像（DB 保存） | `Cache-Control: no-store` のため、表示のたびに DB から読み出す | 件数が少ないため現状は許容。遅い場合はキャッシュの設定を見直す |
| Render 無料枠 | 一定時間アクセスがないと停止し、次の表示が遅くなる | 公開画面はキャッシュで表示できる。応募先へ URL を送る前に一度開いておく。`/health` で起動を確認できる |
| Neon 無料枠 | 休止からの復帰に時間がかかることがある | 初回の遅延は許容する。マイグレーションはプールを通さない接続文字列で実行する |
| Resend | テスト用の送信元では、Resend に登録したアドレスにしか送れない | 通知先は自分だけなので問題ない。独自ドメインを取ったときに送信元を変える |
| ログ | `console.error` のみで、本番と開発の出し分けがない | お問い合わせの本文やメールアドレスは出力しない（エラーの種類や状態コードのみ）。出し分けは必要になった時点で検討 |
