## 2. プロジェクト概要

### 目的

- これまでの仕事で培った「人に寄り添う力」と、学習している Web 開発の力を、一つのサイトで伝える
- 作品が増えても、コードを書き換えずに管理画面から登録・並び替えができるようにする
- フロントエンド・バックエンド・データベース・認証をつなぎ、一つの Web アプリとして本番で動かす

### 利用者

| 利用者 | 目的 | 使う画面 |
| --- | --- | --- |
| 閲覧者（サイトを訪れた方。お仕事でつながる可能性のある方など） | 経歴・作品・スキルを知る。必要なら連絡する | 公開画面 |
| 管理者（本人のみ） | 掲載内容を更新する。お問い合わせを確認する | 管理画面 |

### 解決したいことと対応する機能

| 解決したいこと | 対応する機能 |
| --- | --- |
| 作品を増やすたびにコードを直すのは手間 | 管理画面から実績・スキル・画像を登録・更新 |
| 見せたい順番を自分で決めたい | 実績とスキルの表示順を数値で管理 |
| 管理画面を他人に使われたくない | Firebase 認証、管理者 UID の照合、未認証時の 404 |
| 連絡を見逃したくない | お問い合わせの保存、管理画面での一覧、メール通知 |

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 公開画面 | 誰でも見られるトップページ（`/`） |
| 管理画面 | 管理者だけが使える編集画面（`/admin`） |
| 実績 | 制作した作品。画面上の見出しは「実績」 |
| 表示順 | 実績・スキルの並び順を決める数値。小さいほど上に表示する |
| 内部 API キー | Next.js のサーバーと Express だけが知る合言葉。ブラウザには渡さない |

## 4. 機能要件

### 公開画面

| ID | 機能 | 内容 |
| --- | --- | --- |
| P-1 | プロフィール表示 | 日本語名・英語名・見出し・自己紹介・所在地・プロフィール画像。見出しと自己紹介は改行を反映する |
| P-2 | 実績表示 | 表示順に、画像・タイトル・説明・使用技術・GitHub とデモへのリンクを表示する |
| P-3 | スキル表示 | カテゴリーごとにまとめ、表示順にスキル名と説明を表示する。カテゴリーが空のものは「その他」にまとめる |
| P-4 | お問い合わせ | 名前・メールアドレス・本文を送信する。送信中・成功・失敗を画面に表示する |
| P-5 | 管理者ログインへのリンク | フッターから、ログイン画面を別タブで開く |

### 管理画面

| ID | 機能 | 内容 |
| --- | --- | --- |
| A-1 | ログイン・ログアウト | メールアドレスとパスワードでログインする。ログイン状態はセッション Cookie（5日間）で保つ |
| A-2 | アクセス制限 | 未ログイン、または管理者以外が `/admin` を開くと 404 を返す |
| A-3 | プロフィール編集 | P-1 の項目を編集する |
| A-4 | 実績の管理 | 登録・編集・削除・表示順の変更 |
| A-5 | スキルの管理 | 登録・編集・削除・表示順の変更 |
| A-6 | 画像の登録・更新 | プロフィール画像と作品画像。JPEG・PNG・WebP、1MB まで |
| A-7 | お問い合わせ一覧 | 新しい順に最大50件を表示し、未読数を出す。既読・未読を切り替える |
| A-8 | 公開画面の確認 | 公開画面を別タブで開くリンク |

### システム

| ID | 機能 | 内容 |
| --- | --- | --- |
| S-1 | データの保存 | プロフィール・実績・スキル・お問い合わせ・画像を PostgreSQL に保存する |
| S-2 | 入力チェック | 必須項目・文字数・形式を、ブラウザ・Next.js のサーバー・Express の3か所で確認する |
| S-3 | 公開画面のキャッシュ | 表示用のデータを Next.js のサーバー側に1時間とっておく。管理画面で保存したら作り直す |
| S-4 | お問い合わせの送信制限 | サイト全体で、10分間に10件まで。超えたら保存しない |
| S-5 | メール通知 | お問い合わせを受け付けたら、管理者へメールで知らせる。通知に名前・メールアドレス・本文は含めない。通知に失敗しても保存は取り消さない |

### 主な入力の上限

| 対象 | 項目と上限 |
| --- | --- |
| プロフィール | 名前・日本語名・所在地 100文字、見出し 200文字、自己紹介 2000文字 |
| 実績 | タイトル 100文字、説明 2000文字、使用技術 1つ50文字・20個まで、URL 2048文字 |
| スキル | 名前・カテゴリー 100文字、説明 500文字 |
| 表示順 | 0〜9999 |
| お問い合わせ | 名前 100文字、メールアドレス 254文字、本文 2000文字 |
| 画像 | JPEG・PNG・WebP、1MB |

## 5. 非機能要件

| 項目 | 内容 |
| --- | --- |
| 表示速度 | 公開画面は、とっておいたデータ（S-3）があればそれを使い、API の起動を待たずに表示する。デプロイ直後などでデータがないときは、API の起動に数十秒かかることがある（Render 無料プランの仕様） |
| セキュリティ | 通信は HTTPS。DB の接続情報・内部 API キー・Firebase Admin の認証情報はサーバー側だけで扱う。セッション Cookie は `httpOnly`。Express に helmet を使う。SQL は Prisma 経由で組み立てる |
| 個人情報 | お問い合わせの名前・メールアドレス・本文は DB にだけ保存し、ログやメール通知には出さない |
| スパム対策 | 内部 API キー、ハニーポット（人には見えない入力欄）、送信回数の制限 |
| 対応端末 | パソコンとスマートフォンのブラウザ。スマートフォンでは1列、パソコンでは複数列で表示する |
| アクセシビリティ | 画像に代替テキスト、新しいタブで開くリンクに説明、キーボード操作時の枠線を付ける |
| 運用 | `main` へのマージで本番に自動反映。CI（整形チェック・Lint・テスト・ビルド）を通ったものだけをマージする |
| 費用 | 無料プランの範囲で運用する（Vercel・Render・Neon・Firebase・Resend） |

## 6. 外部サービス

| サービス | 用途 | 渡すデータ |
| --- | --- | --- |
| Firebase Authentication | 管理者のログイン | 管理者のメールアドレスとパスワード（Firebase が管理） |
| Resend | お問い合わせのメール通知 | 受信日時と管理画面の URL のみ |
| Vercel／Render／Neon | 画面・API・DB の公開 | アプリのデータ一式 |

## 7. 制約・前提

- 管理者は本人1人。複数の管理者や権限の違いは扱わない
- 閲覧者のアカウント登録やログインは行わない
- お問い合わせへの返信は、管理画面ではなく、本人のメールから行う
- 画像は DB に保存する。画像の削除機能はない（差し替えのみ）
- 独自ドメインは取得していない（`vercel.app` の URL で公開）

## 8. 課題要件との対応

| MUST 要件 | 対応内容 |
| --- | --- |
| TypeScript・Next.js App Router | フロントエンドで使用 |
| TypeScript・Express | バックエンドで使用 |
| Prisma・PostgreSQL | データの取得・登録・更新・削除で使用 |
| Next.js のサーバー機能から Express へアクセス | Server Component・Server Action・Route Handler で対応 |
| プロフィール・実績・スキル | PostgreSQL のデータを公開画面へ表示（P-1〜P-3） |
| プロフィール画像 | PostgreSQL へバイナリデータとして保存（A-6） |
| お問い合わせフォーム | Server Action から Express を経由して保存（P-4） |
| Firebase 認証・認可 | メール・パスワードログイン、Admin SDK、管理者 UID で対応（A-1・A-2） |
| 未認証時の HTTP 404 | `/admin` への未認証アクセスで対応（A-2） |
| 画像の登録・更新 | 管理画面から実行（A-6） |
| Firebase 設定の環境変数管理 | 手元は `.env.local`、本番は Vercel の環境変数で管理し、Git には含めない |
